# Design Document

## Overview

This design replaces the local SQLite/HTTP workshop with a production-shaped AWS deployment. The booking concierge logic from `agent_workshop/booking.py` moves to a Lambda function backed by DynamoDB. Real Strands SDK agents (Supervisor + Availability Specialist) replace the deterministic routing switch. Static assets are served from S3. Infrastructure is defined in a CDK Python stack that can be synthesised and deployed in a single command.

The design preserves all workshop safety constraints: synthetic data only, no SMS provisioning, no real patient data, emergency-escalation path bypasses the LLM entirely.

### AgentCore Runtime vs Direct Strands SDK

```python
# aws/lambda/agents.py — invoke_supervisor()
def invoke_supervisor(supervisor: Agent, message: str) -> str:
    runtime_arn = os.environ.get("AGENTCORE_RUNTIME_ARN")
    if runtime_arn:
        # AgentCore Runtime path
        import boto3
        client = boto3.client("bedrock-agentcore-runtime", region_name=REGION)
        response = client.invoke_agent(
            agentRuntimeArn=runtime_arn,
            sessionId=os.urandom(8).hex(),
            inputText=message,
        )
        output = "".join(
            chunk.get("chunk", {}).get("bytes", b"").decode()
            for chunk in response.get("completion", [])
        )
        return output or str(supervisor(message))
    else:
        # Direct Strands SDK fallback
        return str(supervisor(message))
```

## Components and Interfaces

### Lambda Handler (`aws/lambda/handler.py`)

The handler is the single entry-point for all three API routes. It performs input validation, routes to the appropriate domain function, and serialises the response.

```python
import json
from config import validate_env   # raises at cold-start if required vars missing
from booking_ddb import DynamoBookingStore
from agents import build_supervisor

store = DynamoBookingStore()       # module-level: reused across warm invocations
supervisor = build_supervisor()    # Strands agents initialised once

def handler(event, context):
    method = event.get("httpMethod", "")
    path   = event.get("path", "")

    try:
        if method == "POST" and path == "/chat":
            return _handle_chat(event)
        if method == "POST" and path == "/booking/race":
            return _handle_race()
        if method == "GET" and path == "/metrics":
            return _ok(store.summary())
        return _error(404, "Not found")
    except (ValueError, KeyError, TypeError) as exc:
        return _error(400, str(exc)[:160])
    except Exception:
        import logging
        logging.exception("Unhandled exception in booking Lambda")
        return _error(500, "Demo operation failed")

def _handle_chat(event):
    body = json.loads(event.get("body") or "{}")
    customer   = body.get("customer", "").strip()
    text       = body.get("text", "").strip()
    message_id = body.get("message_id", "").strip()
    if not customer or not text or not message_id:
        raise ValueError("customer, text and message_id are required")
    if len(customer) > 100 or len(text) > 2000 or len(message_id) > 128:
        raise ValueError("input exceeds demo limits")
    reply = store.on_message(customer, text, message_id, supervisor)
    return _ok(reply.to_dict())

def _handle_race():
    from booking_ddb import run_slot_race
    result = run_slot_race(store)
    if result["confirmed"] != 1:
        import logging
        logging.error("Race invariant violated: %s", result)
        return _error(500, "Race invariant violated")
    return _ok(result)

def _ok(body):
    return {"statusCode": 200, "headers": _cors_headers(),
            "body": json.dumps(body)}

def _error(status, message):
    return {"statusCode": status, "headers": _cors_headers(),
            "body": json.dumps({"error": message})}

def _cors_headers():
    return {
        "Content-Type": "application/json",
        "Access-Control-Allow-Origin": "*",
        "Access-Control-Allow-Methods": "POST,GET,OPTIONS",
    }
```

### Strands Agents (`aws/lambda/agents.py`)

The `availability_specialist` is decorated with `@tool` and registered in the supervisor's `tools` list, following the [Strands agent-as-tool pattern](https://strandsagents.com/docs/learning/multi-agent-patterns-agents-as-tools/).

```python
import os
from strands import Agent, tool
from strands.models.bedrock import BedrockModel

MODEL_ID = os.environ["BEDROCK_MODEL_ID"]
REGION   = os.environ.get("AWS_REGION", os.environ.get("AWS_DEFAULT_REGION", "eu-west-1"))

@tool
def query_available_slots(doctor: str) -> str:
    """Read available appointment slots for a doctor from DynamoDB. Read-only."""
    from booking_ddb import DynamoBookingStore
    store = DynamoBookingStore()
    slots = store.list_available_slots(doctor)
    if not slots:
        return f"No available slots for {doctor} in the demo calendar."
    return "\n".join(
        f"{s['slot_id']}: {s['clinician']} at {s['site']} on {s['starts']}"
        for s in slots
    )

def build_supervisor() -> Agent:
    model = BedrockModel(model_id=MODEL_ID, region_name=REGION)

    availability_specialist = Agent(
        name="availability_specialist",
        description="Find appointment availability in the demo calendar. Read-only.",
        model=model,
        tools=[query_available_slots],
        system_prompt=(
            "You are a read-only appointment availability assistant. "
            "Look up available slots and report them. "
            "You MUST NOT claim to have created, confirmed, or cancelled any booking. "
            "Only the booking domain service can commit a reservation."
        ),
        callback_handler=None,
    )

    supervisor = Agent(
        name="supervisor",
        model=model,
        tools=[availability_specialist],
        system_prompt=(
            "You are an appointment-booking concierge supervisor. "
            "Delegate availability questions to availability_specialist. "
            "IMPORTANT: You must NEVER claim to have committed a booking. "
            "Booking confirmation is performed by a separate authoritative service after your response. "
            "All clinicians, patients, and appointment times are fictional demo data."
        ),
        callback_handler=None,
    )
    return supervisor
```

## Error Handling

| Scenario | Mechanism | HTTP Response |
|---|---|---|
| Missing required env var | `config.py` sys.exit at cold start | Lambda never starts; deployment alert surfaced in CloudWatch |
| Oversized request body | API Gateway body size limit 8192 B | 413 |
| Invalid field lengths | Lambda input validation | 400 `{"error": "..."}` |
| Slot already booked | `ConditionalCheckFailedException` caught in `confirm_booking` | 200, `state=CONFLICT` |
| Duplicate message_id | Idempotency read returns stored reply without calling agent | 200, same reply as first call |
| Unhandled Lambda exception | `except Exception` block in handler; stack trace logged, not returned | 500 `{"error": "Demo operation failed"}` |
| Emergency wording in message | Direct escalation path in `on_message` — Supervisor Agent never invoked | 200, `state=ESCALATED`, reply contains emergency services text |
| AgentCore Runtime unavailable | `invoke_supervisor` falls back to direct Strands SDK call | Transparent to caller; no HTTP error |

## Data Models

### DynamoDB Single-Table Key Schema

The table uses `pk` (String, partition key) and `sk` (String, sort key). At demo scale all entity types share one table; `pk` prefix distinguishes entity types.

| Entity | pk | sk | Attributes |
|---|---|---|---|
| Slot | `SLOT#{slot_id}` | `SLOT#{slot_id}` | clinician, site, starts |
| Booking | `BOOKING#{slot_id}` | `BOOKING#{slot_id}` | reference, customer, booked_at |
| Conversation | `CONV#{customer}` | `CONV#{customer}` | state, offered_slot |
| Idempotency | `MSG#{message_id}` | `MSG#{message_id}` | response_json, ttl (epoch seconds, 24 h) |
| Escalation | `ESCALATION#{ticket_id}` | `ESCALATION#{ticket_id}` | customer, reason |

### BookingReply Data Transfer Object

`BookingReply` is unchanged from `booking.py` and serialises to the same JSON shape consumed by the existing web UI:

```python

class BookingReply:
    agent: str
    state: str        # OFFERED | CONFIRMED | CONFLICT | CANCELLED | ESCALATED | NEED_INFO | NO_SLOTS
    message: str      # agent reasoning text (live Bedrock response) or escalation text
    customer: str
    slot_id: str | None = None
    reference: str | None = None  # only set when state=CONFIRMED

    def to_dict(self) -> dict: ...
```

### Race Condition Implementation

```python
# booking_ddb.py
def run_slot_race(store: DynamoBookingStore, contenders: int = 20) -> dict:
    import threading
    from concurrent.futures import ThreadPoolExecutor
    # 1. Write 20 CONV# records all offering slot R-1730 to race-customer-{n}
    for i in range(contenders):
        store.table.put_item(Item={
            "pk": f"CONV#race-customer-{i:02d}",
            "sk": f"CONV#race-customer-{i:02d}",
            "state": "OFFERED",
            "offered_slot": "R-1730",
        })
    barrier = threading.Barrier(contenders)
    def work(i):
        barrier.wait(timeout=10)
        reply = store.on_message(
            f"race-customer-{i:02d}", "YES", f"race-confirm-{i}", supervisor=None
        )
        return reply.state
    with ThreadPoolExecutor(max_workers=contenders) as pool:
        results = list(pool.map(work, range(contenders)))
    return {
        "contenders": contenders,
        "confirmed": results.count("CONFIRMED"),
        "conflicts": results.count("CONFLICT"),
        "booking_rows": 1,
    }
```

## Testing Strategy

### Approach

The testing strategy uses two complementary layers:

- **Property-based tests** (Hypothesis) for universal invariants: slot uniqueness, idempotency, input validation, race isolation, and agent response propagation. Each property runs ≥ 100 generated inputs.
- **Example-based unit tests** (pytest) for CDK snapshot assertions, specific routing scenarios, and configuration validation.
- **Integration tests** are intentionally limited to post-deploy smoke checks (verify three seed slots exist, verify API Gateway returns 200) because testing AWS service behaviour requires real infrastructure.

### CDK Snapshot Tests

Use `aws_cdk.assertions.Template` to verify synthesised CloudFormation:

- DynamoDB KeySchema has `pk` (HASH) and `sk` (RANGE).
- Lambda environment contains `BEDROCK_MODEL_ID`, `DYNAMODB_TABLE_NAME`, `AGENTCORE_RUNTIME_ARN`.
- S3 bucket `BlockPublicAcls` and `BlockPublicPolicy` are `True`.
- API Gateway resources exist for `/chat` (POST) and `/booking/race` (POST) and `/metrics` (GET).
- IAM policy actions are exactly `dynamodb:GetItem`, `dynamodb:PutItem`, `dynamodb:UpdateItem`, `dynamodb:Query`, `bedrock:InvokeModel` — no wildcards.

### Property Tests (Hypothesis)

Each property test tags its assertions with `Feature: aws-interactive-deployment, Property {n}: {text}` for traceability.

**Property 1 — Slot Booking Mutual Exclusion**: Generate a random slot ID and a random N (2–50 concurrent callers). Mock DynamoDB `put_item` to simulate the conditional write atomically in-process. Assert exactly one CONFIRMED and N−1 CONFLICT.

**Property 2 — Idempotency**: Generate random `message_id` strings and random `BookingReply` instances. Store the reply, then call `on_message` again with the same `message_id`. Assert the second reply is equivalent and no agent was invoked.

**Property 3 — Input Validation**: Generate `customer` strings > 100 chars, `text` strings > 2000 chars, and `message_id` strings > 128 chars in any combination. Assert the handler returns HTTP 400.

**Property 4 — Race Isolation**: Generate random non-race customer records. Run `run_slot_race`. Assert all pre-existing non-race records are unchanged.

**Property 5 — Emergency Escalation**: Generate messages containing at least one of `["urgent", "chest pain"]` in any position, case, or surrounding context. Assert `BookingReply.message` contains the emergency services substring and no agent invocation occurred.

**Property 6 — Agent Reasoning Propagation**: Generate random non-empty strings as mock agent output. Assert `BookingReply.message` equals that string exactly.

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Slot Booking Mutual Exclusion

*For any* slot identifier and any set of N concurrent confirmation attempts (N ≥ 2), exactly one attempt returns a `BookingReply` with `state = "CONFIRMED"` and all remaining N−1 attempts return `state = "CONFLICT"`. This holds regardless of the number of concurrent callers, their order of arrival, or the slot identifier used.

**Validates: Requirements 2.3, 2.4, 6.3**

### Property 2: Idempotency of Message Processing

*For any* valid `message_id` and any message that produces a `BookingReply` on first processing, calling `on_message` a second time with the same `message_id` returns a `BookingReply` structurally equivalent to the first reply, without invoking the Supervisor Agent a second time.

**Validates: Requirements 2.5**

### Property 3: Input Validation Rejects Oversized Fields

*For any* combination of `customer`, `text`, and `message_id` values where at least one field exceeds its defined maximum length (100, 2000, 128 characters respectively), the Lambda handler returns HTTP 400 with a non-empty `error` field, without writing any record to DynamoDB.

**Validates: Requirements 4.4**

### Property 4: Race Isolation — Non-Race Customers Unaffected

*For any* set of non-race customer conversation records present in DynamoDB before `run_slot_race` is invoked, those records are identical (same `state`, same `offered_slot`) after `run_slot_race` completes. The race operates exclusively on `race-customer-{n}` identities.

**Validates: Requirements 6.5**

### Property 5: Emergency Escalation Bypasses the Agent

*For any* message string that contains at least one of the trigger phrases `"urgent"` or `"chest pain"` (case-insensitive), the resulting `BookingReply.message` contains the substring `"For a medical emergency, contact local emergency services immediately."` and the Supervisor Agent is never invoked for that message.

**Validates: Requirements 8.3**

### Property 6: Agent Reasoning Propagation

*For any* non-empty string returned by the Supervisor Agent, the `BookingReply.message` field produced by the Lambda handler equals that string (no truncation, no wrapping in a static template).

**Validates: Requirements 3.5**

### Property 7: Booking Conditional Write Atomicity

*For any* slot identifier, after exactly one `CONFIRMED` booking exists in DynamoDB for that slot, all subsequent `confirm_booking` calls for the same slot return `state = "CONFLICT"` and the total number of `BOOKING#` items for that slot in DynamoDB remains exactly 1.

**Validates: Requirements 2.3, 6.3**
